# Summary of Core Requirements Given for `tasks.md`

- Derive tasks from `plan.md` and the approved specification.
- Focus primarily on front-end development.
- Keep tasks small, ordered, and checkable.
- Trace every task to a requirement (R#) or ADR.
- Follow the sequencing defined in `plan.md`.
- Remove dependency ranges (`T1-T5`) and use explicit task references.
- Remove duplicate and self-dependencies.
- Reduce redundant implementation work.
- Minimize the chance of rewriting code later.
- Introduce shared state before dependent features.
- Centralize filtering logic before connecting search and filter controls.
- Define persistence structure and validation before implementing loading/saving.
- Treat accessibility as an audit and correction phase.
- Treat responsive design as refinement after major UI elements exist.
- Match the uploaded task guide.
- Use the exact Quick Self-Check section from the guide.
- Deliver the final document as `tasks.md`.
